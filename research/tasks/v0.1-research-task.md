# System Tempo v0.1 research task

## Objective

Determine whether a proposed System Tempo factor represents only a reparameterization of time or survives that no-go test as a candidate for stronger physical analysis.

The task is intentionally narrower than validating System Tempo as a physical theory.

## Input class

v0.1 accepts deterministic, classical, finite-dimensional autonomous ODE systems of the form:

```text
dX/dt = Gamma(X, p, ...) F(X, p, ...)
```

or a component-wise extension with one tempo factor per state component.

## Primary research question

Can one admissible monotonic change of time parameter remove the proposed tempo factor while preserving the model's relevant invariant structure?

## Required outputs

Every completed v0.1 run should ultimately produce a canonical-contract-valid immutable input,
deterministic classification, scoped verdict, explicit reason, discovered reparameterization
when available, declared preserved invariants where justified, and replayable provenance.
The current runner does not yet guarantee canonical JSON-Schema parity because it validates
through the slightly more permissive Pydantic mirror documented in the hypothesis contract.

## Acceptance criteria

1. A common positive scalar factor is classified reproducibly as `pure_time_reparameterization` when the transformation is regular.
2. Distinct component tempo factors are not promoted to validated physics; they are only candidates that survived the first no-go filter.
3. Unsupported or undecidable inputs return `inconclusive` rather than fabricated certainty.
4. The same input can be replayed without an LLM and yields the same verdict under the same code/dependency environment.
5. Scientific verdict semantics are independent of UI, agent, or prompt wording.
6. Execution failure is distinguishable from failure of a hypothesis.

## Non-goals

v0.1 does not establish a new theory of time, replace relativity, make cosmological claims, solve quantum measurement, infer experimental confirmation, or use numerical scale as a substitute for an invariant argument.

## Next-task trigger

A hypothesis proceeds beyond v0.1 only if it survives the common-scalar no-go test and identifies a concrete candidate observable, invariant, subsystem relation, or obstruction to one global reparameterization.

The next research stage is therefore not "simulate more" by default. It is to formulate the cheapest deterministic test capable of destroying the surviving claim.
